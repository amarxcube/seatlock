# SeatLock

Event booking platform with assigned seating: customers hold exact seats, pay with Stripe (test mode), and get QR-code tickets. The core requirement is **zero double bookings under contention**.

Design docs live in [docs/](docs/README.md) and are approved: PRD → architecture → database → API → wireframes, plus ADRs. Read the relevant section before changing a module. Where code and docs disagree, the docs win unless the PR updates them.

## How work is done here

- Work follows [docs/delivery-plan.md](docs/delivery-plan.md), phase by phase. **No code for a phase until its plan is approved by the owner; no next phase until the current one is signed off.**
- Keep the status board, checklists and change log in the delivery plan up to date in the same PR as the work.
- `main` is protected: every change goes through a branch (`phase/<n>-<name>`, or `chore/<name>` for small changes) and a PR.
- Commits follow Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`), with the phase as scope where useful (`feat(holds): ...`).
- Significant decisions (structure, data, security, external deps, >1 day to undo) get a new ADR in `docs/adr/` in the same PR ([ADR-0001](docs/adr/0001-record-architecture-decisions.md)).
- API changes start in [docs/api/openapi.yaml](docs/api/openapi.yaml); the code follows the contract, not the other way round ([ADR-0010](docs/adr/0010-api-design-first-openapi.md)).

## Repository layout

```
apps/web          React SPA (Vite, TanStack Query, Tailwind, React Router, Zustand)
apps/api          NestJS: main.ts (HTTP + WebSocket), worker.ts (BullMQ, sweeper, outbox relay)
packages/shared   zod schemas, enums, constants (HOLD_TTL, MAX_SEATS_PER_HOLD)
packages/api-client  typed client generated from openapi.yaml; never edit by hand
```

`apps/*` may import `packages/*`; packages never import apps; `web` and `api` never import each other.

## Non-negotiable rules

**Booking correctness** ([ADR-0004](docs/adr/0004-seat-hold-concurrency.md), [database.md §5](docs/database.md#5-concurrency-and-locking))

- Postgres is the only source of truth for seat state. Never use Redis for locks or seat ownership.
- Holds use one conditional `UPDATE` inside a transaction; seat rows are locked in `ORDER BY seat_id` order. Isolation stays READ COMMITTED.
- Expiry is computed (lazy reclaim); never make correctness depend on the sweeper running.
- Raw SQL (`$queryRaw` / `$executeRaw` tagged templates only, always parameterised) is allowed **only** in the `holds`, `inventory` and `payments` repositories. Everything else uses Prisma.
- Business invariants that SQL can express go in the database (CHECK, UNIQUE, partial indexes), marked `-- manual:` in migrations.
- Realtime broadcasts happen **after** commit.

**Side effects** ([ADR-0007](docs/adr/0007-background-jobs-bullmq-outbox.md), [ADR-0009](docs/adr/0009-payments-stripe-payment-intents.md))

- Emails, PDFs and refunds are written to the `outbox` table in the same transaction as the business change; never enqueued or sent inline in a request.
- Every job handler is idempotent.
- Orders are fulfilled only in the Stripe webhook, never from the client redirect. Order state only moves forward.

**Data conventions** ([ADR-0012](docs/adr/0012-money-and-time-conventions.md), [database.md §1](docs/database.md#1-conventions), [api.md §1](docs/api.md#1-basics))

- Money: integer cents, `_cents` in SQL, `Cents` in JSON (`priceCents`). No floats. Only the frontend formats money.
- Time: `timestamptz` in UTC; API sends ISO-8601 with `Z`; venues carry an IANA time zone; display in the venue's zone.
- IDs: UUIDv7 generated by the application.
- SQL `snake_case`; JSON `camelCase`; enums are lowercase snake_case strings.

**API** ([api.md](docs/api.md))

- Base path `/api/v1`. Errors are RFC 9457 `application/problem+json` with a stable `code` from the [error catalog](docs/api.md#error-catalog) and a `requestId`. Add new codes to the catalog.
- Another user's resource returns `404`, not `403`.
- All input is validated with zod schemas from `packages/shared` ([ADR-0011](docs/adr/0011-shared-validation-zod.md)); never define the same rule twice.

**NestJS layering**

- Controller: parse/validate, call service, map to DTO. Service: business rules, transactions, state checks, ownership checks. Repository: data access.
- Modules talk through services or domain events, never each other's repositories.

**Security**

- No secrets in code or commits; every env var is documented in `.env.example` and validated by zod at boot.
- Organizer ownership (`organizer_id = currentUser.id`) is checked in services, not only guards.
- Never log tokens, passwords, card data or full Stripe payloads.

## Testing

- Integration tests run against real Postgres and Redis (Testcontainers), never mocks for the database.
- Any change to holds, checkout, fulfilment or the sweeper must keep the concurrency suite green (100+ parallel holds → exactly one winner).
- `holds` module coverage stays ≥ 80%.
- Bug fixes come with a test that fails without the fix.

## Commands

See the [README](README.md#commands) for the full list. The ones to run before every PR:

```bash
pnpm turbo run lint typecheck test build   # fast checks
pnpm test:integration                      # real Postgres/Redis via Testcontainers; contract tests
pnpm format:check
```

- After changing `docs/api/openapi.yaml`: `pnpm generate` and commit `packages/api-client/src/schema.d.ts`.
- After changing `apps/api/prisma/schema.prisma`: `pnpm --filter @seatlock/api db:migrate`, then review the generated SQL.
- Every new endpoint's integration tests call `expectContract(res, '<operationId>')` for each response they produce ([ADR-0014](docs/adr/0014-contract-enforcement-by-response-validation.md)).
- Local Postgres is on port **5433**. On this Windows machine, Node needs `NODE_USE_SYSTEM_CA=1` (TLS-intercepting proxy), and Podman must stay rootless.
